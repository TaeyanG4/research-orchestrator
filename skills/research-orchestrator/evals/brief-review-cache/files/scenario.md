# Review-cache scenario

Use a fresh unified work project, slot A, explicit session cache-author, guards off, collector off, and the actual local environment. The dated H-A-01/s1 event records `Decision: changed` and `Review artifact: result.txt`; its result reverses an archive-retention decision. The fixture artifact initially contains `retain one verified copy`. A synthetic reviewer identity `fixture-reviewer` approves scope `H-A-01/s1:after` after the event timestamp. For the directory variant, reference `review/` containing `result.txt` and obtain a matching PASS receipt before warming the cache. Change the artifact content to `retain two verified copies` or replace PASS with FAIL after warming. These synthetic receipts exist only to test cache dependencies, not to claim substantive review. For the budget variant, reference `large/` holding members that total more than 64 MiB, obtain its PASS receipt through the receipt API outside any brief, then capture one ordinary brief and one `check_project.py` run without changing anything else. For the link variant, add a directory link (a junction on Windows) inside the reviewed `review/` directory after warming, and capture the next ordinary and compact brief. For the unreadable variant, make one member of `review/` (or its subdirectory) unreadable after warming, or, where permissions cannot be changed, simulate the read failure in process by raising `PermissionError` from that member's lookup; capture two consecutive compact briefs. For the growth variant, hash a one-byte `grow.log` under a two-byte brief budget while a wrapper appends 99 bytes before the file is opened and, in a second run, after its first byte is read; record the raised error and the bytes actually read.
